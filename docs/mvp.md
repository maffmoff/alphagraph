# MVP — 研究のネットワークを最短で立てる

作成: 2026-08-27 / 状態: 決定（ユーザー決定「研究のネットワークが最優先」2026-08-27）

`fable-concept.md` §7 の優先順位を、実際に何を作るかまで具体化した文書。ここに書いてある範囲がMVPであり、それ以外は明示的にMVP外とする。

---

## 1. 成功条件

> **自分以外のDIDが、自分以外の論文を再現または反証し、その署名が台帳に載り、さらに後続の論文がそれを引用する。**

この一周が**1回**起きたらMVPは成功。順位表もvault収益もこの条件には入らない。ネットワークが存在することの最小の証拠は「他人が他人の研究に触った記録」であって、成績ではない。

## 2. 中心の設計判断: 計算は運営でなくネットワークが負担する

MVPを戦略型・ラウンドから始めない理由は、**誰がコードを実行するか**にある。

| | 実行者 | 運営の負担 | 最初の証拠まで |
|---|---|---|---|
| ラウンド方式 | 運営が全員のコードを毎日サンドボックス実行 | 可用性・セキュリティ・決定性契約を全部背負う。**参加者増が運営の負債** | 約90日 |
| 再現方式 | 再現する側が自分のマシンで実行し、出力ハッシュ一致を署名して台帳へ | ハッシュ照合のみ。計算基盤を運用しない。**参加者増が計算力** | 数日 |

ネットワーク効果が最優先である以上、後者を先に立てる。戦略型は最長のクリティカルパス（サンドボックス＋target計算＋ユニバース固定＋90日＋規制確認）を持つが、**実証・観察型と反証型は既存の部品で数日で閉じる**。非戦略型はエッジ減価の懸念が小さく即時公開を選べる（§2、猶予は上限であって義務ではない）ため、commit-revealのreveal側も初日から回る。

規制確認・法務がクリティカルパスから完全に外れることも大きい。実金が動かないので、人間承認待ちのままMVPは完走できる。

## 3. 評価の所在（ユーザー決定 2026-08-27）

**論文の内容の評価は、従来の学術論文と同じく、参加者の署名付き評価と引用ネットワークによって決まる。** 運営が評価器を定義するのは同質なラウンドの内側だけで、論文そのものの価値判断には運営は入らない。

帰結:

- **IC・IC Sharpe・MMCは「論文の評価」ではない。** ラウンドという狭い場での測定値であり、戦略型がその場に出た時にだけ意味を持つ。5型のうち4型には存在しない量なので、これを全体の評価軸に昇格させない
- **単一スコアに集約しない**（§3の既定を維持）。評価は署名付き定性判定（再現・反証・リスク指摘・追試）として積まれ、評価者自身の質も履歴になる。評価する側もDIDを賭ける
- **引用は符号と種別を持つ。** 依拠・発展・反証・否定を区別して記録し、**符号なしの被引用数を評価に使わない**。壊れた論文ほど反証で引用されて高評価になる倒錯は、学術の被引用数指標が実際に抱えている欠陥であり、最初から型で塞ぐ
- **相互引用の共謀（引用カルテル）は検出可能性で扱う。** 台帳は公開・append-onlyなので引用グラフ全体が誰にでも解析できる。防止機構は作らず、DID履歴と引用の向きを見せることで検出を可能にする（台帳と同じ「防止でなく検出」の信頼モデル）

## 4. 作るもの（4つ）

既存コードとの距離が近い順。

1. **論文パッケージの封緘** — 主張＋分析コード＋データハッシュ＋**親論文のハッシュ引用（種別つき）**を1個のJSONに束ね、`hashJson` ＋ DID署名して台帳に追記。`cli.mjs propose` が原型。差分は引用フィールドと、戦略スキーマ固定を外した汎用化
2. ~~**等級1再現コマンド**~~ → **実装・検証済み（2026-08-27）**。`alphagraph reproduce --report FILE --data CSV` が再実行・照合・判定を行い、署名可能な `alphagraph-reproduction-v1` を出力する。`attest --verdict reproduced` で署名し `verify` で第三者検証できるところまで通した。契約の詳細は §8
3. **append-onlyの台帳連鎖**（`ledger-design.md` 部品1）— `prevHash` 付き1イベント1ファイルを公開gitへ。cloneが監査レプリカ。取込口は当面CI相当でよい
4. ~~**静的生成の論文ページと引用グラフ**~~ → **実装・検証済み（2026-08-27）**。`alphagraph site --ledger DIR --output DIR` が台帳から決定的にページを生成する。**生成時刻を含まない**ので、同じ台帳からは常に同じ `pageSha256` になり、誰でも再生成して「画面と台帳の一致」を確かめられる。引用グラフは種別ごとに線種と色を分け（依拠=灰破線 / 発展=青実線 / 反証=赤実線 / 否定=赤破線）、被引用は**種別ごとにしか数えない**。台帳の文字列は投影時に必ずエスケープする

`core.mjs` の安定ハッシュと `did.mjs` のEd25519 did:keyはそのまま使う。

| FLOP | 未発行。台帳が先、トークンが後 |

## 6. 種まきと最初の燃料

- **自分が最初の参加者になる**: 観察型論文を3〜5本、封緘して即時公開する。`market-data.mjs` で取れる公開データで足りる。他人が真似できる**形式の見本**が要るので、量より1本目の完成度
- **反証レーンが最も安い集客装置**: 作るより壊す方が参加コストが低い。実質的な反証は論文に昇格し反証者の業績になる（§2）ので制度側は完成済み
- **ここだけ金を出す**: 観察型には収益が直結しないため、動機が「履歴が残る」だけになる。**成立した再現・確定した反証へのUSDC懸賞**が最小の燃料。vault収益と無関係に自己資金の範囲で始められる
- **参加障壁の床**: 鍵生成〜封緘登録を1スクリプトに。ドキュメントはエージェントが自走できる形式で置く（§7レバー2）

## 7. ラウンドの位置

捨てない。**台帳に後から挿す評価の場の一つ**に戻す。MVPで作る封緘・引用・再現の3機構はラウンドでもそのまま使うので手戻りはない。開通は参加者数への感度で段階的に行う。

| 出すもの | 条件 |
|---|---|
| 共通target・サンドボックス日次実行・日次IC全公開 | 戦略型レーン開通時（N=1でも成立する） |
| 順位表（bootstrap CI・P(A>B) 併記） | 参加論文が閾値を超えてから |
| vault執行とMMC分配 | 上記＋規制確認・数値の人間承認 |

小Nでは順位表もMMCも退化する（等ウェイトrank合成メタに自分を直交化するので、N=2なら残差は実質 ±(A−B)/2、N=1で寄与ゼロ。90観測のIC Sharpeにブロック長5日以上のbootstrapを掛ければ P(A>B) は0.5付近に張り付く）。集客に効くのは「日付の決まった開催」であって順位表ではないので、順位と分配は人が集まってから出す。

## 8. 決定性契約（実装・検証済み 2026-08-27）

MVPの技術的な核だった「等級1再現の決定性契約」は実装して検証した。実装は `src/repro.mjs`、CLIは `alphagraph reproduce --report FILE --data CSV`。

**発見された問題**: 実装前の成果物形式では、同一コード×同一データの**正直な再実行が別ハッシュになった**。差分は `createdAt`（実行時刻）と `proposal.sha256`（そのcreatedAtが伝播したもの）の2箇所のみで、`metrics`・`gate`・`data`・`split` は完全一致していた。計算は決定的だが、メタデータが再現判定を壊していた。等級1再現をハッシュ一致で定義している以上、これは**正直な再現者が全員不合格になる**欠陥だった。

**契約**: 正規形から以下を落とす。`REPRO_CONTRACT` として `src/repro.mjs` に定義し、契約自体をハッシュ固定してある（`contractHash`）。

| 落とすもの | 理由 |
|---|---|
| `createdAt` | 実行時刻。著者と再現者で必ず異なる |
| `proposal` | 封緘物のラッパ。中の `createdAt` が伝播する。コードとの結び付きは `strategyHash` が担う |
| `reproduction` | この契約で計算した値そのもの。自己参照を避ける |
| `data.label` | 保存ファイル名。再現者は別名で保存する。データ本体は `data.sha256` が釘付けする |
| `data.provenance` | 取得元メタデータ。`fetchedAt` を含む。内容の同一性は `data.sha256` が担う |

**2段ハッシュ**: `metricsHash`（`strategyHash` + `dataSha256` + `metrics` + `gate`）と `canonicalHash`（正規形全体）を別々に出す。これで不一致の切り分けが機械的になり、**誰かが裁く必要が消える**。

| verdict | 条件 | 意味 |
|---|---|---|
| `match` | canonicalHash 一致 | 等級1再現が成立 |
| `environment-drift` | metricsHash 一致・canonicalHash 不一致 | 実行環境かエンジン版の差。数値結果は再現できている |
| `mismatch` | metricsHash 不一致 | 論文側の欠陥か決定性の破れ |
| `different-subject` | strategyHash か dataSha256 が違う | そもそも等級1再現ではない |

不一致時は差分のパス（例 `metrics.outOfSample.sharpe`）を列挙する。

**環境間不変性**: `test/golden-repro.test.mjs` が固定入力に対する正規形ハッシュを定数で釘付けし、`.github/workflows/ci.yml` が3 OS × Node 20/22/24 のマトリクスで常時検証する。浮動小数の差はここで落ちる。定数の変更は `engine.version` の意図的更新か契約変更の時だけで、台帳イベントとして扱う。

**残る中央性（正直に記録する）**: 正規形の定義権は運営が握る。何を落として何を残すかが再現の合否を決めるので、「運営は論文の価値判断に入らない」（§3）と言ってもこの一点だけは残余の中央性として残る。契約をハッシュ固定して公開し、変更を台帳イベントにすることで、**定義権を消すのではなく検出可能にする**——台帳と同じ信頼モデルで扱う。

## 8b. 封緘・台帳・データ基盤（実装・検証済み 2026-08-27）

§4の作るもの1・3と、データ基盤へのアクセスを実装し、実データで通した。

- **論文パッケージ**（`src/paper.mjs`）: 5型・主張・機構・払い手・検証条件・データ釘・**種別つき引用**（依拠/発展/反証/否定）を1個の決定的なJSONに束ねる。反証型は対象論文の名指しが必須。パッケージに時刻は入らない（封緘の時刻は台帳イベントが持つ）
- **台帳**（`src/ledger.mjs`）: `prevHash` で連なる1イベント1ファイルのhash連鎖。全イベントにDID署名。`alphagraph ledger-verify` が連鎖・署名・連続性を一括検査する。1文字の改竄で `hash,canonical` の不一致として検出されることを確認
- **データ基盤**（`src/data-source.mjs`）: Hyperliquid公開info APIとBinance公開market-data APIのみを許可リストで通す。**資格情報の経路を構造的に塞ぐ**——許可外ホスト・非HTTPS・URL userinfo・認証ヘッダ・資格情報らしきクエリを送信前に拒否し、モジュールは `process.env` を一切読まない（テストがソースを検査して保証する）。実測でHL perp 176銘柄と日次OHLCVを無認証で取得
- **封緘で分かったこと（漏洩を1件塞いだ）**: 引用の `note` は自由文なので、猶予期間中の論文でも機構を書けてしまう。実際に最初の封緘で「出来高と価格変化の結合が前提」という機構がそのまま公開部分に載った。**猶予期間中は `note` を伏せ、種別と対象ハッシュだけ公開する**よう修正した。系譜は伏せる対象ではないので残す。伏せても論文ハッシュは変わらないため、reveal時の一致検証は成立する

**実際に載せたもの**: ローカルのテーゼ台帳から5本を封緘し、引用系譜を繋いだ。

| id | 型 | 公開 | 引用 |
|---|---|---|---|
| ag-d-0001 | dataset | 即時 | — |
| ag-e-0001 | empirical | 即時 | depends-on: ag-d-0001 |
| ag-s-0001 | strategy | 猶予90日 | depends-on: ag-d-0001, ag-e-0001 |
| ag-s-0002 | strategy | 猶予90日 | builds-on: ag-s-0001 |
| ag-s-0003 | strategy | 猶予90日 | depends-on: ag-d-0001 |

この5本を `alphagraph site` で投影すると、引用グラフは ag-d-0001 を根として深さ3まで伸びる（ag-d-0001 → ag-e-0001 → ag-s-0001 → ag-s-0002、ag-s-0003 は ag-d-0001 の直下）。ag-d-0001 の被引用は「依拠 4」、ag-s-0001 は「発展 1」と、種別つきでのみ表示される。

台帳に載るのは `paperHash / type / id / disclosure / citations / dataPins` だけで、主張・機構・払い手・検証方法は一切出ない（検査済み）。全文は `private/` と `artifacts/` に残り、どちらもgit管理外。

ag-e-0001は実際に走る観察型論文で、HL公開データのBTC/ETH/SOL日次に対し `examples/papers/ag-e-0001-volume-return-coupling.mjs` が決定的なJSONを出す（|リターン|と出来高の同時順位相関 0.519〜0.559、出来高上位20%日の|リターン|中央値は下位20%の約5.1〜5.5倍）。2回実行して出力ハッシュ一致を確認済み。

## 8c. Technocore上での往復（実測 2026-08-27）

読み取り・書き込みの両方向を実サービスに対して通した。使ったのは一時部屋（`e-` 接頭辞・900秒で消える）。

**通ったこと**: 署名付き書き込みが着信し、`from` が我々のDIDになった（無署名投稿は `from` がニックネームになるので、**読み取り側でも署名の有無は区別できる**——署名そのものは返らないが、DIDが立っていることはサーバが書き込み時に検証した証跡になる）。本文・nonceが署名対象と一致し、本文中の論文ハッシュが手元の台帳と一致することを確認した。

**実測で見つけて直した2件**:

1. **書き込みは届いたのに、クライアントには応答が返らなかった。** 最初の投稿はタイムアウトし、追って503が返った。しかし部屋を読むとメッセージは着信済みで、再送すると `400 nonce is not greater than …, a signed URL is single-use` が返った。署名URLは単回限りで、nonceはその鍵・その部屋での前回より大きくなければならない。**盲目的な再送は害にしかならない。** `publishTechnocoreAttestation` にタイムアウト（既定15秒）と、失敗時に**再送せず部屋を読み戻して着信を確かめる**経路を入れた
2. **告知していたハッシュが台帳から辿れなかった。** 封緘済みレコードは全文を含むため、そのハッシュは台帳のどこにも現れない。`seal` が公開用の commitment 成果物（台帳イベントの `data` と同一）も書くようにした。`event.canonical` に `hashJson(data)` が入っているので、**告知ハッシュから台帳イベントを誰でも特定できる**。実際に第三者の立場で照合し、commitment告知だけが `台帳 seq 2 (ag-e-0001)` に解決することを確認した

**位置付けの確定**: Technocoreは**公開の広報路であって証拠層ではない**。理由は非永続性ではなく、①読者が署名を独立検証できない、②`fsync: false` で書き込みの耐久性が保証されない、の2点（`fable-concept.md` §6の実測を参照）。告知は「台帳に載っているものを指す公開の指差し」として使い、正本は常に自前の台帳に置く。

2. 引用の粒度（論文ハッシュ単位か、論文内の主張単位か）と種別の語彙（依拠・発展・反証・否定＋α）
3. 懸賞額の初期設定と、二重取り・自作自演を抑える最小ルール（DID履歴で足りるか）
3b. Technocore告知の耐久性をどう補うか（`/kv/` の永続ノートに台帳headを置く案があるが、`fsync: false` は同じく効く。HyperEVMアンカーの前倒しが要るかは賭け金次第）
4. 戦略型以外（実証観察・データ・手法）の成果物スキーマと、それぞれの正規形
