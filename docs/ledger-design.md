# 台帳の仕組み — 透明性ログ設計（ドラフト）

作成: 2026-08-26 / ブランチ: `design/fable-testnet` / 状態: ドラフト
前提: `docs/fable-concept.md` §6（Technocoreは議場・忘れる設計、正本は自前、アンカーはHyperEVM）

優先順位の注記（fable-concept §7）: 現段階で作るのは部品1・2（hash連鎖＋論文登録のcommit-reveal）まで。部品3（HyperEVMアンカー）と部品5（検証CLI）は賭け金が大きくなってからの後回し装備。

## 型の選択: ブロックチェーンではなく透明性ログ

TradeCoreの台帳はCertificate Transparency / Sigstore型の**透明性ログ**とする。

- 書き手（sequencer）は運営者ただ一人。ただし改竄・遅延・削除は**誰にでも検出可能**。
- 信頼モデルは「防止」でなく「検出」。これによりコンセンサス機構が不要になり、追記専用ファイル＋静的生成という最小構成で成立する。
- 内容の真正性は各イベントの**著者DID署名**が担い（運営者は偽造できない）、順序と存在時刻は**hash連鎖＋外部アンカー**が担う。

## 部品1: hash連鎖イベントログ（正本）

- イベント = 正規化JSON 1件。`seq`, `at`, `type`, `data`, `prevHash`, `authorDid`, `signature` を持ち、`hash = SHA-256(正規化本文)`。`src/testnet.mjs` の `appendEvent` パターンを踏襲。
- 1イベント1ファイル、content-addressed命名で公開gitリポジトリに格納。gitのMerkle構造により履歴書き換えは全cloneとの不一致で発覚。**cloneが監査レプリカ**。
- 大きい成果物（提出の中身、run結果、target計算の入出力）は成果物ストア（別リポジトリまたはオブジェクトストア）に置き、台帳にはハッシュのみ。

## 部品2: 取込口とcommit-reveal（封緘の実装）

- 取込口は署名・スキーマ・レート制限（DIDごと、fable-concept §5）を検証して追記する小さなサービス（またはCI相当）。
- **commit-revealの適用対象は論文登録**（fable-concept §2・§4により日次提出は存在しない。コード封緘がコミットメントそのもの）:
  1. **commit（封緘）**: 論文登録時に `SHA-256(コード＋主張＋検証条件)` ＋DID署名を台帳へ。優先権はこの時点で確定。
  2. **reveal（全文公開）**: 猶予期間満了時にコード全文を公開し、台帳がハッシュ一致を検証（特許型・fable-concept §2）。公開が報酬と論文の正式地位の条件。公開拒否は論文取り下げとして履歴に残る。
- 登録済み論文の日次シグナルは運営のサンドボックス実行で生成され、`SIGNALS_GENERATED` イベント（シグナルのハッシュ）として毎日台帳に積まれる。
- **disclosure schedule**: 各論文は封緘時に公開予定（猶予期間の満了日）を台帳イベントとして持ち、公開・延期・取り下げの状態遷移もイベントとして記録する。

## 部品3: HyperEVMアンカー（存在時刻の外部証明）

- 新規イベントのMerkle rootを**毎時＋各締切直後**にHyperEVMへ刻む（calldataまたは最小コントラクトのイベント）。
- 各イベントは「遅くともアンカー時刻には存在した」を獲得。運営者による締切後commitの遡及挿入（backdating）はアンカーとの矛盾で検出される。
- 執行層・支払いレールと同一チェーンのため運用が増えない（fable-concept §6）。Merkle包含証明はイベントファイル横に保存。

## 部品4: 静的投影（画面）

- 台帳→ページは決定的な静的生成（プロトタイプ `docs/testnet/` の delta方式が原型）。GitHub Pagesで公開。
- 生成器コードもハッシュ固定で公開。誰でも再生成して「画面と台帳の一致」を検証できる。

## 部品5: 検証CLI

- `tradecore verify-ledger`: 連鎖の連続性／全署名／アンカー包含証明／commit-reveal整合を一括検査。既存 `verify` の拡張。
- 独立DIDによる定期検証の実行を**検証労働として報酬対象**にし、監査を自走させる（fable-concept §5の検証労働支払いと接続）。

## 作らないもの

- 独自チェーン・コンセンサス（書き手は一人、必要なのは検出可能性のみ）
- 全データのオンチェーン化（チェーンにはMerkle rootのみ）
- リアルタイムDB（追記専用ファイル＋静的生成で可用性要求を下げる）

## 既存コードとの対応

| 部品 | 既存の原型 | 追加実装 |
|---|---|---|
| hash連鎖 | `testnet.mjs` appendEvent | ファイル分割・正規化・authorDid/署名フィールド |
| 署名 | `did.mjs`（Ed25519 did:key） | そのまま |
| 成果物運用 | `evidence/` ＋ attestations | 成果物ストアの分離 |
| 静的投影 | `docs/testnet/` プロトタイプ | 実台帳からの生成に接続 |
| 検証 | `cli.mjs verify` | verify-ledger拡張 |
| 取込口 | なし | commit-reveal検証つき追記サービス |
| アンカー | なし | 毎時Merkle root投稿＋包含証明 |
